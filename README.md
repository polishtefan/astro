# astro

Натальные карты в стилистике co-star. Расчёты — Swiss Ephemeris прямо в браузере.

## Запуск

```bash
npm install     # postinstall сам разложит wasm и эфемериды в static/
npm run dev
```

| Команда | Что делает |
| --- | --- |
| `npm run dev` | дев-сервер |
| `npm run build` / `npm run preview` | прод-сборка и её просмотр |
| `npm run check` | svelte-check (типы + разметка) |
| `npm run verify` | сверка расчётного ядра с независимыми формулами |
| `npm run sweph:assets` | перекопировать ассеты Swiss Ephemeris вручную |

## Публикация

Сайт статический — сервера нет: Swiss Ephemeris считает в браузере, город
браузер ищет сам в Open-Meteo, хранить нечего. Поэтому он живёт на GitHub
Pages: `https://polishtefan.github.io/astro/`.

* `adapter-static` собирает готовые файлы в `build/`, страница пререндерится
  (`src/routes/+layout.ts`).
* На Pages сайт в подпапке `/astro`. Путь задаётся переменной `BASE_PATH` при
  сборке; локально её нет, и дев-сервер работает из корня. Пути к движку и
  эфемеридам идут через `base` из `$app/paths`, к шрифтам Vite сам делает
  относительными.
* Собирает и публикует GitHub Actions (`.github/workflows/deploy.yml`) при
  каждом push в `main`: `npm ci` (postinstall кладёт эфемериды в `static/`),
  `npm run check`, `npm run verify`, сборка. Если сверка расчётов не
  сошлась — сайт не публикуется.
* Один раз в настройках репозитория: Settings → Pages → Source: «GitHub
  Actions».

Проверить сборку с подпапкой локально: `BASE_PATH=/astro npm run build` и
раздать `build/` по адресу `/astro/`.

## Ключевая механика

Карта — чистая функция от `(данные рождения, дата наблюдения)`.

* **Натал** — дата наблюдения равна моменту рождения.
* **Транзиты** — дата наблюдения равна `now` или значению скраббера.
* **Синастрия** — вторая карта, партнёра, посчитанная от его места и момента
  рождения.

Рендер один и тот же: `Wheel.svelte` получает натальные положения, опционально
транзитные и список аспектов. Появление транзитов = появление внешнего кольца
и линий аспектов транзит → натал.

Дома всегда считаются от **места и момента рождения** — это неподвижная рамка
карты, транзиты ложатся на неё. Поэтому `computeChart` берёт дома от рождения
даже когда положения планет считает на другую дату.

## Геометрия колеса

ASC слева (9 часов), долгота растёт против часовой стрелки:

```
screenAngle = 180 − (lon − ascendant)
x = cx + r·cos(screenAngle)
y = cy + r·sin(screenAngle)
```

Кольца (центр 320,320): знаки 300 / 252, транзитные планеты 232, натальные 208,
круг аспектов 190. Холст шире колеса (`viewBox` начинается в отрицательных
координатах): за кольцом знаков стоят подписи домов.

Оформление колеса выросло из Сотиса. Одно время рядом жил второй стиль под
Геокульт с переключателем; его убрали, а вместе с ним и описание стилей
данными — с одним стилем ветвление в компоненте только мешало читать код.

Глифы разводятся по минимальному угловому зазору (10°). Точки истинного
градуса лежат **ровно на окружностях**: натальные — на круге аспектов,
транзитные — на внутреннем крае кольца знаков.
Линий от точки к глифу нет: на коротком расстоянии точка и так читается как
принадлежащая ближайшему глифу, а дюжина поводков поперёк кольца — это только
шум.

**Переходы между режимами.** Рамка карты при смене режима стоит на месте:
ASC всегда строго слева. Раньше при появлении транзитов всё колесо
поворачивалось на −4°, и горизонт перекашивался. Теперь внешнее кольцо и хорды
аспектов перетекают: старые гаснут за 250 мс, новые проявляются за 450 мс.
Шаги ползунка переходов не запускают — меняется только набор, а не его
положение. При системной настройке «уменьшить движение» всё меняется сразу.
Поиск точных транзитов при входе в режим ждёт 600 мс, пока колесо доиграет
переход: он синхронный, и иначе кольцо с хордами возникали рывком вместе со
списком. Пока он идёт, место под список держится его полной высоты (288 px вместе с
подсказкой под ним), а сам список проявляется: иначе блоки ниже резко уезжали
вниз, когда одна строка «Searching…» сменялась списком.

Панель при смене режима проявляется заново целиком (250 мс). Режимы
переставляют почти всю панель — в синастрии сверху встают партнёр и аспекты, у
Positions появляется колонка, внизу пропадают натальные аспекты, — и если
проявлять только новые блоки, всё ниже всё равно прыгает. Пока панель
прозрачна, перестановки не видно. Фильтры и свёрнутые секции живут в скрипте и
при этом не сбрасываются.

Совпадение натальных точек с кругом аспектов не случайно: хорда аспекта
начинается ровно в точке планеты, поэтому одна метка работает на два смысла.

Градус планеты — настоящий надстрочник, приклеенный к глифу: сбоку и чуть
выше. Сторона выбирается по половине колеса и по тому, где лежат точки:
у натала подпись смотрит наружу (влево в левой половине, вправо в правой), у
транзитов — внутрь. Так она не ложится на круг точек и всегда однозначно
принадлежит своему глифу.

Раньше подпись ставилась на собственный радиус со сдвигом по дуге. От круга
она уходила, но уплывала от глифа и оказывалась между соседями — было неясно,
чья она. Привязка к глифу важнее, чем единое полярное правило.

Дома подписаны снаружи колеса, как в Сотисе: римская цифра с градусом
надстрочником (`XI¹⁴`), а у четырёх углов вместо цифры имя — `As`, `Ic`, `Ds`,
`Mc`. Линия куспида идёт от аспектного круга насквозь через кольцо знаков и
чуть выступает наружу, поэтому подпись читается как её продолжение. Внутри
колеса номеров домов нет — там и без них плотно.

Градус берётся целым и округляется **вниз** — то же правило, что в таблице
планет и в любых эфемеридах. Сотис показывает порядковый номер градуса (на
22°45′ он напишет `23`, у нас будет `22`); мы за ним не идём, иначе в одном
экране оказалось бы два разных счёта.

Знак градуса в подписи обязателен: куспид на 0°45′ даёт `0`, и голая ноль-цифра
читается как отсутствие данных, а `0°` — как значение.

## Оформление

Две независимые оси, обе живут атрибутами на `<html>` и сохраняются в
localStorage:

| Атрибут | Значения | Что меняет |
| --- | --- | --- |
| `data-theme` | `dark` · `light` | фон и чернила: ночь — графит, день — серая бумага |
| `data-palette` | `mono` · `elements` | цвет знаков и значков аспектов |

В палитре «стихии» цвет получают знаки (огонь — красный, земля — зелёный,
воздух — жёлтый, вода — синий) и значки аспектов по типу (напряжённые —
красный, трины — зелёный, секстили — синий). Сами линии аспектов остаются
серыми. `Моно` означает отсутствие цвета во всём колесе.

Тона традиционные, а **насыщенность у всех одна** (~30%) и светлота одна
(~56%). Раньше насыщенность гуляла от 34 до 73%: цвета выпрыгивали вперёд
поодиночке и на графите с зерном читались как неон. У светлой темы те же тона
и та же насыщенность, но светлота ниже (~38%) — иначе цвет тонет в фоне.

У знака цветом обводятся только дуги, внешняя и внутренняя, встык. Радиальные
разделители остаются нейтральными: граница у двух соседних знаков общая, и
одна линия не может быть двух цветов. Первая версия решала это зазорами между
секторами — кольцо рассыпалось на отдельные плашки.

Страница собрана на одной сетке полей (`.shell`, до 1160 px): шапка, заголовок
карты, разделительная линия и обе колонки делят общий `max-width` и отступы,
поэтому сходятся по левому и правому краю.

Панели хватает фиксированной ширины (340–430 px): в ней короткие строки
таблицы, и растягивать её значит гнать глаз через пустоту. Всё остальное место
забирает колесо — до 680 px, дальше не растёт, чтобы на большом мониторе не
разрасталось до абсурда. Раньше каждый блок задавал их сам и края
расходились.

Верхняя строка — одна полоса: слева переключатель режима «Natal · Transits ·
Synastry», справа настройки и «birth data». Все элементы в одном текстовом
стиле — слова капсом, активное подчёркнуто — и выровнены по базовой линии,
поэтому читаются как единый ряд.

Раньше на месте переключателя стояла подпись режима («Natal chart» /
«Bi-wheel»), а сам переключатель был справа от имени — в рамке, с залитой
активной кнопкой. Режим оказывался назван дважды, а переключатель был самым
громким элементом страницы и спорил с именем; на узком экране он ещё и
упирался в настройки. Одна кнопка с перебором режимов не подошла: режимов
три, и по кругу непонятно, что будет следующим, а в выпадающем меню два из
трёх спрятаны.

Ниже — имя, строки о карте, линия, и уже за ней две колонки: колесо и панель.

Внизу — подвал во всю ширину, за такой же линией, как под шапкой: чем
считается карта (Swiss Ephemeris, © Astrodienst), что происходит с данными
(ничего не хранится, наружу уходит только поиск города в Open-Meteo), метод
(Placidus, истинный узел, мажорные аспекты) и автор. Раньше вместо него была
сноска в конце панели — она висела под одной колонкой, а не закрывала
страницу. Когда появится публичный репозиторий, в подвал добавится ссылка на
исходники: для публичного сайта её требует AGPL.

Ни чистого чёрного, ни чистого белого: тёмная тема — графит с серебряными
чернилами, светлая — серая бумага с угольными. Контраст мягче, ближе к плёнке,
чем к экрану.

Поверх страницы лежит плёночное зерно (`body::after`). Шум генерирует сам
браузер фильтром `feTurbulence` во встроенной SVG-картинке — никакого файла
текстуры, вес пара сотен байт; плитка 180×180 повторяется, `stitchTiles`
сшивает края, чтобы не проступала сетка повторов. Слой закреплён относительно
окна и не прокручивается — зерно «лежит на стекле», как на плёнке. Режим
наложения `overlay` работает в обе стороны: осветляет тёмное, затемняет
светлое. Сила крутится одной переменной `--grain`, своей у каждой темы: на
графите шум съедается и нужно больше, на светлой бумаге тот же процент уже
сорит по тонким линиям колеса.

Переключатели темы и знаков вместе с кнопкой «birth data» стоят в шапке
справа. Форма выпадает из кнопки: в шапке для неё нет места, а раскрывать
её во всю ширину значило бы сдвигать вниз всю страницу при каждом открытии.
Закрывается по Escape и по клику мимо. Клик «мимо» ловится на pointerdown, а не
на click: к моменту click разметка внутри формы может уже смениться (выбор
города перерисовывает список), и проверка «клик внутри» дала бы ложный промах.

Всё, что рисует колесо, ходит через CSS-переменные, поэтому смена темы не
требует правок в компонентах. Начальные атрибуты ставит короткий синхронный
скрипт в `src/app.html` — иначе на светлой теме мелькал бы чёрный фон.

## Тексты

Интерфейс английский. Все тексты собраны в `src/lib/copy.ts` одним объектом —
менять формулировки в одном месте, а не искать по компонентам.

Раньше здесь жили два словаря и машинерия языков: определение по cookie и
`Accept-Language`, серверный хук, контекст Svelte, переключатель EN/RU. Всё это
удалено вместе с русским — от него оставались только лишние слои.

Не переводится и не менялась общая астрологическая нотация: подписи домов
`As`/`Ic`/`Ds`/`Mc`, символы знаков и планет, `℞`.

Город в форме можно набирать и кириллицей: геокодер сам выбирает язык поиска
по тому, чем набран запрос (украинские буквы → `uk`, русские → `ru`, иначе
`en`) — иначе «Харьков» с английским языком находит посёлок под Волгоградом.
Но названия в ответе придут на языке запроса, а кириллицу шрифты не рисуют.

## Даты и время

В `BirthData` дата всегда ISO (`1995-06-14`), время — 24 часа (`21:20`).
Всё, что видит человек, идёт через `formatDate` / `parseDate` / `parseTime`.

Поля даты и времени в форме — свои текстовые, а не `<input type="date"/"time">`.
У нативных формат отображения диктует локаль операционной системы: на en-US это
месяц/день/год и AM/PM, и повлиять на это со страницы нельзя. Свои поля дают
день.месяц.год и 24 часа независимо от системы, а рядом с временем показывается
12-часовой эквивалент — `21:20` подписано как `9:20 PM`.

Ввод прощающий: разделитель любой, можно `1.1.2000` или восемь цифр подряд —
при уходе из поля значение нормализуется. Год ограничен 1800–2400: это диапазон
подключённых файлов эфемерид.

## Блоки панели

Три сворачиваемых блока под колесом, каждый про своё:

**Положения** — планета, градус со знаком, ретроградность; в режиме транзитов
добавляется вторая колонка с текущим положением. Градус, знак и ℞ разложены по
колонкам фиксированной ширины, иначе знаки вставали бы каждый на своё место и
колонка выглядела рваной.

Узлов два: северный ☊ и южный ☋. Южный — не отдельное тело: у Swiss Ephemeris
для него нет номера, он всегда ровно напротив северного. Берётся тот же истинный
узел из SE и разворачивается на 180° (`opposite` в `bodies.ts`), так что
точность та же. Аспектов у узлов нет — ни у одного, ни у другого. Подпись
«Node» стала «North Node»: рядом с южным голое «Node» двусмысленно.

**Дома** — куспид каждого дома и планеты, которые в него попали. В режиме
транзитов дома заселяют **транзитные** планеты, а не натальные: куспиды всё
равно натальные (рамка карты неподвижна), а смысл режима — что происходит
сейчас; натальную расстановку видно в режиме натала. Подпись колонки меняется
вместе с содержимым («In house» → «Transiting»), иначе непонятно, чьи это
планеты. Дом сначала
стоял колонкой в «Положениях», но там он спорил с двумя наборами координат в
режиме транзитов и мельчил таблицу. Отдельным блоком видно и границы домов, и
их наполнение — это и есть то, ради чего дома смотрят. Углы карты (I, IV, VII,
X) выделены плотностью.

**Аспекты** — мажорные аспекты натальных планет друг к другу и к углам, с
орбом. Порядок — как в таблице положений: все аспекты Солнца, потом Луны,
Меркурия и так далее; внутри блока планеты в том же порядке, углы после них.
Аспект планеты так находится глазами сразу. Раньше список шёл от самого
точного к широкому, но искать в нём конкретную планету было неудобно. Значок аспекта красится
по типу тем же цветом, что на колесе и в списке точных транзитов.

Над списком — фильтр по планете, в том же виде, что у точных транзитов:
пресет «All» и ряд глифов, выбор одиночный. В натале ряд один: аспект двух
своих планет симметричен, поэтому «Mars» показывает все аспекты Марса, с какой
бы стороны пары он ни стоял. В синастрии рядов два, подписанных именами
(«Poli», «Alex»): стороны разные, и их можно сочетать — «моя Венера → что
угодно» или «моя Венера → его Плутон». Состояние фильтра у натала и синастрии
своё: переключение режима не сужает неожиданно другой список.

В натале блок стоит в конце панели. В синастрии тот же блок поднимается
наверх, под партнёра, и показывает аспекты между картами. В транзитах его нет:
на колесе лежит сетка транзит → натал, и таблица про саму карту рядом с ней
сбивает с толку. «Положения» и «Дома» есть во всех трёх режимах.

## Аспекты

| Аспект | Угол | Планеты | К углу | Транзит | Линия |
| --- | --- | --- | --- | --- | --- |
| Соединение | 0° | 8° | 8° | 1° | не рисуется |
| Секстиль | 60° | 4° | 5° | 1° | тонкая сплошная |
| Квадрат | 90° | 6° | 5° | 1° | пунктир |
| Трин | 120° | 6° | 5° | 1° | тонкая сплошная |
| Оппозиция | 180° | 8° | 8° | 1° | пунктир |

Если в натальной паре Солнце или Луна — к орбу +2°, в том числе к углам.

**Откуда числа.** Единого стандарта орбов нет, даже Solar Fire не навязывает
таблицу, а даёт наборы под задачу. Планетные орбы — середина современного
консенсуса (соединение и оппозиция шире всех, секстиль уже всех), надбавка
светилам — самая общепринятая поправка к нему.

Углам — свои орбы по двум причинам. Соединению и оппозиции оставлены 8°:
планета у угла звучит громко. Остальным аспектам 5°: углы висят на времени
рождения, 4 минуты ошибки сдвигают ASC примерно на градус. И главное — орб
одинаков для аспектов, которые смотрят на одну ось с двух концов (трин к MC =
секстиль к IC). С планетными орбами, 6° у трина и 4° у секстиля, в списке
оказывалась половина пары.

Транзитам — 1° на всё. Список точных транзитов от орбов не зависит, а вот хорды
транзит → натал на колесе с натальными 8° разрастались до трёх десятков линий,
большая часть которых уже не действует. Из общепринятых 1–2° взят нижний:
колесо показывает, что точно сейчас, а «когда» — дело списка. Медленным
планетам и 1° даёт недели (Сатурн в орбе 3–8 недель); при 2° его хорда висела
бы до четырёх месяцев. Пустое колесо в какой-то день — честный ответ «ничего
точного», а не дефект. Все правила — в `natalOrb` / `transitOrb`
в `aspects.ts`.

**Аспекты к углам.** Кроме планет между собой сетка включает аспекты планет ко
всем четырём углам — ASC, IC, DSC, MC — в списке «Аспекты», на колесе и в
точных транзитах. Орбы у углов свои — см. таблицу выше. Углы попарно противоположны, поэтому аспект к оси
виден с обоих концов: «Марс в оппозиции ASC» стоит в списке рядом с «Марс в
соединении с DSC». Это сознательно — у каждого угла свой смысл, и аспект читают
от того конца, к которому он ближе. Промежуточные куспиды не берём: аспекты к
ним почти никто не читает. Пары углов между собой исключены — это геометрия
карты, а не аспекты.

На колесе углы отмечены на круге аспектов пустым кольцом: сплошная точка —
планета, кольцо — угол. Без этого хорду к ASC не отличить от хорды к планете,
которая стоит в градусе от него.

## Синастрия

Третья вкладка рядом с «Natal / Transits». Устроена как транзиты: внешнее
кольцо — не небо на дату, а планеты второго человека. Рамка карты (дома,
углы) — твоя: вопрос синастрии «куда в моей жизни попадают его планеты».

**Партнёр** вводится формой наверху панели — на месте даты и шкалы
транзитов, это та же роль «с чем сравниваем». Форма та же, что для своих
данных (`BirthForm`), только с кнопкой «Compare». После ввода сворачивается
в имя, строку данных и «edit». Координаты в пустой форме — не 0, а пусто:
иначе без выбранного города карта молча посчиталась бы для точки 0°, 0°.
Хранится партнёр, как и всё остальное, только в памяти вкладки.

**Аспекты** между картами идут в панели первыми — в синастрии это главное.
«От» — твои планеты и углы, «к» — планеты партнёра; чья планета слева, а чья
справа, видно по рядам фильтра над списком — они подписаны именами в том же
порядке. Отдельной строки заголовка у таблицы нет: в ней оставались только
«ORB» и «Poli → Alex», и под фильтром висела почти пустая строка. Порядок — как в таблице
положений. Орбы натальные (с надбавкой светилам и правилами для углов):
это сравнение двух неподвижных карт, а не движение, как у транзитов. Углы
партнёра пока не участвуют — на колесе у них нет своей метки.

**Positions** — две колонки, подписанные именами. **Houses** — какие планеты
партнёра попали в твои дома: дом пересчитывается по твоим куспидам, а не
берётся из его карты.

## Точные транзиты

В режиме транзитов под скраббером — список моментов, когда транзитная планета
образует точный аспект к натальной точке: «Jupiter opposite Neptune — 30 SEP
2026, 23:14». Клик по строке ставит колесо ровно на этот момент; любое движение
ползунка возвращает обычный режим.

Вернуться на сегодня — клик по подписи «today» под серединой шкалы. Отдельной
кнопки «back to today» больше нет: она была видна всегда, даже когда ползунок
уже на сегодня, и дублировала эту подпись. На сегодня «today» — тихая подпись,
как «-6 mo» и «+6 mo» рядом; в другой дате или на выбранном точном транзите она
ярче и при наведении подчёркивается.

**Как ищется.** Для пары «транзитная планета → натальная точка» и аспекта с
углом A берём f(t) = λ(t) − (натал + A), приведённое к (−180°, 180°]. Аспект
точный там, где f проходит через ноль:

1. Грубо — шаг в сутки по окну, ловим смену знака. Быстрее всех в списке
   Меркурий (до ~2.2°/сутки), поэтому переход между соседними отсчётами не
   проскочит. Скачок f через ±180° отсекается: там знак меняется, но планета на
   другой стороне круга.
2. Точно — бисекция найденного интервала, 20 делений: 1 сутки / 2²⁰ ≈ 0.08 с.

Секстиль, квадрат и трин бывают по обе стороны от натальной точки, поэтому
для них проверяются две точки φ, для соединения и оппозиции — одна.
Ретроградный проход помечается ℞: при попятном движении медленная планета
проходит одну точку до трёх раз, и в списке это видно.

**Сворачивание.** «Точные транзиты» и «Положения» сворачиваются щелчком по
заголовку: списки длинные, и в режиме транзитов панель иначе уезжает далеко
вниз. Состояние живёт в памяти вкладки — это выбор на время работы, а не
настройка оформления вроде темы. У свёрнутой секции содержимое убирается из
разметки, а не прячется атрибутом `hidden`: у элементов с заданным `display`
класс перебивает `hidden` по приоритету, и они остались бы видны.

**Что в списке.** Окно — полгода в обе стороны от сегодня, как у скраббера,
поэтому клик всегда попадает в его диапазон. Натальные точки — планеты плюс
четыре угла: ASC, IC, DSC, MC.

Соединение хордой не рисуется, поэтому клик по «Jupiter conjunct DSC»
подсвечивает оппозицию к ASC: это тот же момент и та же линия.

Над списком — два независимых фильтра, по одному на каждую сторону аспекта.
Каждый ряд подписан, как колонка таблицы, — иначе два одинаковых ряда глифов не
отличить:

```
TRANSITING                    SLOW  ALL
☉ ☽ ☿ ♀ ♂ ♃ ♄ ♅ ♆ ♇
TO NATAL                            ANY
☉ ☽ ☿ ♀ ♂ ♃ ♄ ♅ ♆ ♇
```

**Transiting** — кто движется: пресеты «Медленные» (Юпитер–Плутон, по
умолчанию, около 25 событий за год) и «Все» (плюс Солнце, Меркурий, Венера и
Марс — около 370 событий, поиск ~130 мс) или одна планета — например Сатурн,
когда вопрос про работу. Выбор одиночный: под вопрос «что покажет Сатурн» это
удобнее мультивыбора — не приходится снимать четыре лишние планеты.

**To natal** — к чему: любая натальная точка или одна планета — «всё, что
касается моей Венеры». Выбор точки переключает «Slow» на «All»: при «Slow» к
одной точке за год приходит одно-два события, а вопрос — про всё, что к ней
подходит. Выбранную планету не трогает: «Сатурн → Солнце» задают осознанно.
Пресеты стоят в строке подписи своего ряда, так видно,
что «Slow/All» — про движущиеся планеты, а «Any» — про натальные точки.

Фильтры сочетаются: «Сатурн → что угодно» (обзор), «Все → Венера» (тема),
«Сатурн → Солнце» (одна пара). Это один список, в который входят с двух
концов, — толкование пары от способа входа не меняется: транзитная планета
действует, натальная точка принимает. Считаются только выбранные планеты, а
лишние натальные точки отбрасываются до поиска, а не фильтруются из готового
списка. Пустой список объясняется словами для конкретного сочетания: «Nothing
exact from Saturn to natal Sun…».

Кнопок углов (ASC · IC · DSC · MC) в фильтре нет, хотя одно время были третьим
рядом. Слова среди двух рядов глифов ломали сетку и читались тяжело, а фильтр
«только к углам» нужен редко. Сами углы не пропали: аспекты к ним ищутся
всегда и стоят в списке при «Any» вперемешку с планетами. Если фильтра по углу
начнёт не хватать, запасной вариант — две кнопки осей AC и MC в конце
натального ряда.

**Луна — особый случай.** В пресеты она не входит: обходит зодиак за 27 дней и
касается каждой из 96 точек аспектов ежемесячно — около 1250 событий за год
против 370 у всех остальных вместе, в общем списке она утопила бы всё.
Выбрать её кнопкой можно, но окно тогда сужается до месяца в обе стороны
(210 событий): полугодовой список Луны рисуется около двух секунд, и смысла в
нём нет — лунный аспект точен в 14:32 и к вечеру разошёлся, его смотрят,
выбирая день и час. Под списком об этом сказано прямо.

**Как проверено.** `exact.ts` не знает, откуда берутся долготы, — на вход идёт
функция, поэтому его можно гонять в Node на тех же эфемеридах. `npm run verify`
ищет моменты, когда Солнце соединяется, образует квадрат и оппозицию к 0° Овна:
это равноденствия и солнцестояния 2024 года, их время публикует USNO. Все
четыре совпадают в пределах 0.6 минуты — это точность самих данных USNO,
округлённых до минуты.

## Swiss Ephemeris

Пакет `sweph-wasm` — полная сборка SE под WebAssembly. Из `node_modules` в
`static/` копируются:

* `swisseph.wasm` (~570 КБ)
* `sepl_18.se1`, `semo_18.se1`, `seas_18.se1` (~2 МБ) — планеты, Луна и
  астероиды на 1800–2400 гг. Астероидный файл нужен ради Хирона.

Файлы раздаются со своего домена: у `sweph-wasm` в дефолте прописан CDN автора
пакета, и зависеть от него не хочется. Ассеты в `.gitignore` — они
воспроизводятся из `node_modules` скриптом `scripts/copy-sweph-assets.js`,
который висит на `postinstall`.

**Лицензия.** Swiss Ephemeris распространяется под AGPL-3.0 (или по платной
коммерческой лицензии). AGPL требует открывать исходники всем, кто пользуется
сервисом по сети. Для личного инструмента и узкого круга знакомых это ок, но
если проект когда-нибудь станет публичным продуктом — вопрос лицензии придётся
решать отдельно.

## Место рождения

Поле «Место рождения» — поиск по геокодеру Open-Meteo: без ключа, без
регистрации, понимает кириллицу и латиницу, отдаёт названия по-русски. Выбор
города подставляет широту, долготу и **часовой пояс**.

Зона здесь важнее координат. Координаты можно взять откуда угодно, а
сопоставить точку с IANA-зоной без большой базы нельзя, и ошибка в зоне
сдвигает ASC на десятки градусов. Наружу уходит только строка запроса.

Если города нет в базе или нет сети, координаты и зона остаются доступны для
ручного ввода. Когда название в поле разошлось с тем, для которого подставлены
координаты, форма это подсвечивает — иначе карта молча считалась бы по
прежнему месту.
